# Rust Foundry lab series

Follow the [shared course design guide](https://github.com/snowch/cuda-python-lab/blob/main/docs/course-design-guide.md). The directory has one tile for this Foundry; its hub offers numbered labs in the existing curriculum order. A lab has a shareable URL, prerequisite, scoped lesson list and progress, and direct Start / Continue / Review. Existing lesson URLs and storage keys are unchanged.

The primary hub action resumes the last unfinished lesson. If that lesson is complete, advance to the next unfinished lesson, wrapping to earlier gaps. When every lesson is complete, offer Review. Completion remains a learner choice, independent of exercise checks.

Cards use auto-fit columns with a 17 rem minimum: one on narrow phones, two at intermediate widths, three when the content area allows. The introduction stays compact. The concept illustration sits beside it on wide screens, after lab choices on narrow screens. Keep labels and links live text, preserve keyboard focus, and use the existing theme tokens.

Navigation does not start the compiler or create another runtime. Keep the shared Code runner, App status and theme controls; preserve edits, notes, outputs and completion on navigation and restart. Lesson paging stays within a lab; the first and last lesson return to its overview. All labs leads to the hub.

Learning intent: learners should select a manageable sequence, understand its prerequisite, and return directly to their work. Existing readings, examples, practice and reference solutions retain their scope. A completed lab means its lessons were explicitly marked complete; it does not establish proficiency.

Verification covers direct lab URLs and reloads, legacy lesson links, fresh/resume/advance/review, first/last lesson boundaries, browser Back/Forward, saved work, one/two/three column layouts, both themes and keyboard operation. Functional checks do not establish learning effectiveness.
